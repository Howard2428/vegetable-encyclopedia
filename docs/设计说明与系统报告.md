## 一、项目概述

### 1.1 项目背景

随着健康饮食观念的普及，消费者对蔬菜的营养价值、时令性、选购技巧等信息需求日益增长。然而这些知识分散在各类平台，缺乏一个垂直领域的整合工具。本系统为普通消费者提供集蔬菜信息查询、收藏管理、智能推荐于一体的蔬菜百科桌面应用。

### 1.2 系统定位

- 垂直领域的蔬菜百科与推荐系统
- 类比"蔬菜版小红书/大众点评"
- 不涉及进销存、交易、社区功能

### 1.3 核心目标

1. 构建覆盖常见蔬菜品种的信息库（营养、选购、储存、价格）
2. 提供便捷的搜索、分类浏览、热门榜单功能
3. 实现基于Apriori关联规则的智能推荐
4. 支持用户多收藏夹管理、自定义蔬菜清单

## 二、系统架构

### 2.1 架构风格

采用**四层分层架构（Layered Architecture）**，各层单向依赖，职责清晰：

```
┌──────────────────────────────┐
│  表示层（ui/）— PySide6 GUI   │
├──────────────────────────────┤
│  业务逻辑层（service/）        │
├──────────────────────────────┤
│  数据访问层（dao/）            │
├──────────────────────────────┤
│  数据层 — SQLite / MySQL      │
└──────────────────────────────┘
```

### 2.2 模块划分

| 模块 | 职责 | 关键类 |
|------|------|--------|
| 蔬菜信息模块 | 搜索、分类浏览、详情展示、热门榜单 | SearchService, VegetableService |
| 用户中心模块 | 注册登录、收藏夹、自定义清单 | UserService, CollectionService |
| 推荐引擎模块 | Apriori挖掘、关联推荐、时令推荐 | MiningService, RecommendationService |
| 后台管理模块 | 蔬菜CRUD、菜谱导入、系统重置 | AdminWindow |

## 五、核心算法

### 5.1 Apriori关联规则挖掘

使用 `mlxtend.frequent_patterns.apriori` + `association_rules`：

1. 从菜谱JSON中提取蔬菜共现对
2. 构建One-Hot编码事务矩阵
3. Apriori算法挖掘频繁项集（min_support=0.01）
4. 生成关联规则（min_confidence=0.1）
5. 过滤仅保留单前项→单后项规则
6. 清空旧规则库，批量写入新规则

### 5.2 模糊搜索排序

四级相关度：精确名称(0) > 名称前缀(1) > 名称包含(2) > 别名包含(3)

### 5.3 密码安全

- bcrypt (rounds=12) 哈希加密
- 密码强度：≥8位 + 大小写字母 + 数字（至少满足2项）
- 弱密码登录后提醒修改

## 六、数据流

```
用户 → 搜索框/分类导航/时令卡片/热门榜单
     → 蔬菜列表
     → 蔬菜详情（标签页：营养/选购/储存）
     → 关联推荐卡片 → 窗口内跳转
     → 收藏（选择收藏夹）/ 加入清单
     
管理员 → 蔬菜CRUD → 数据库更新
       → 导入菜谱JSON → Apriori挖掘 → 关联规则入库
       → 用户管理 → 重置密码
       → 系统重置 → 清除统计/规则/用户
```

## 七、交互设计要点

- 搜索：回车或点击按钮，输入框右侧有眼睛图标切换密码明文
- 收藏：弹出选择收藏夹对话框，支持当场新建
- 自定义清单：当场新建，无需先到个人中心
- 蔬菜详情：页面内跳转，←返回退历史，✕一键全关
- 按钮样式：内联styleSheet确保所有环境下正常渲染
- 密码框：QAction内嵌眼睛图标，无布局干扰
